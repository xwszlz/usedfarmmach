**日期**：2026-10-15
**分支**：`feat/valuation-calibration`
**相关commit**：`25b9f76`（ASABE 三处缺陷修复，改造前）、本文档对应 commit（复利改造）

## 一、要修的问题

`calcAgeTableResidual()`（`src/lib/valuation/brand-data.ts`）原实现对四段机龄表
全程使用**线性减法**：

```ts
remaining -= yearsLeft * DEPRECIATION_TABLE[i].rate;
```

`DEPRECIATION_TABLE` 声明的语义是「年折旧率」（0-3 年 7%、4-7 年 8%、8-12 年 7%、
13 年+ 5%）。但线性减法把「年率」当成了「年减量」，产生两个可证伪的错误：

### 错误 (a)：名义费率被严重高估

线性减法下，累计衰减 = Σ(rate × 年数)，即 y12 时：

```
1 − (3×0.07 + 4×0.08 + 5×0.07) = 1 − 0.79 = 0.21
```

若真按 7%/年复利，应为 0.93³ × 0.92⁴ × 0.93⁵ = 0.5395。

**实际衰减 36.84%（名义写7%）** —— 名义费率与实际行为差5 倍以上。

### 错误 (b)：y13 触底后永久锁死（硬 bug）

13 年段是 5%/年线性减法，每年减 0.05。从 y13的 0.15 起算：

- y13: 0.10→ 触到 `MIN_RESIDUAL_RATIO = 0.10`
- y14~ y40:全部被 `Math.max(remaining, 0.10)` 夹回 **0.10**

**13 年的机与 40 年的机估值完全相同。** 这不是观点分歧，是数学缺陷。

## 二、候选方案与取舍

| 方案 | y1–y8 | y13 残值 | y30 残值 | 结论 |
|---|---|---|---|---|
| 现行（线性） | 不变 | 0.1000 | 0.1000 | 保留 bug |
| **A 全表复利**（y1–y30 全改） | y7 +22.6%、y8 **+34%** | 0.3808 | 0.2660 | 否决 |
| **C 分段复利**（y1–y8 不动，y9+ 复利） | **一位不动** | 0.2843 | 0.1189 | **采纳** |

### 为什么否决方案 A

1. **作废唯一的专家锚点**。y1–y8 是全系统唯一有外部专家基准验证的区间
   （豆包 TTQ2004 报告：10.14 万 vs 专家 10.45 万，−2.95%）。A 会把这段整体
   上移 0%~34%，且新值无任何专家背书。
2. **超出市场证据**。A 在 y13 给 0.3808，而中国二手市场两个 11–13 年大方捆实测
   残值为 0.293 / 0.315 —— A 比实测高21%~30%。

> 顺带纠正一个此前的错误数字：曾有分析称「全表复利后 y13 升至约 0.22，接近 ASABE
> Balers 的 0.2367」。实测全表复利给到 **0.3808**，比 ASABE 高 61%，并非「接近」。

### 采纳方案 C 的依据

C 在 y13 给 0.2843，与两个独立外部参照对齐：

| 参照 | y13 残值 | C 偏差 |
|---|---|---|
| ASABE D497 Balers 曲线（ANSI 2003 / ORNL Pub11927 Table 2.3） | 0.2367 | C 高 20% |
| 麦赛福格森 2170XD 大方捆 13 年实测（116.7 万 → 36.8 万） | 0.315 | C 低 10% |

C 落在两个参照之间，且**更贴近唯一的中国市场实据**。

## 三、实现要点

```ts
export const AGE_TABLE_LINEAR_MAX_YEAR = 8;

// y1–y8：线性减法，历史行为逐位保持
if (ageYears <= AGE_TABLE_LINEAR_MAX_YEAR) { /* 原逻辑原样保留 */ }

// y9+：以 y8 残值为起点，按各段在 (y8, age] 上的**区间重叠**年数逐段复利
const base = calcAgeTableResidual(AGE_TABLE_LINEAR_MAX_YEAR, category);
let remaining = base;
for (let i = 0; i < DEPRECIATION_TABLE.length; i++) {
  const segStart = i === 0 ? 0 : DEPRECIATION_TABLE[i - 1].maxYear;
  const segEnd = DEPRECIATION_TABLE[i].maxYear;
  const overlap =
    Math.min(ageYears, segEnd) - Math.max(AGE_TABLE_LINEAR_MAX_YEAR, segStart);
  if (overlap > 0) remaining *= Math.pow(1 - DEPRECIATION_TABLE[i].rate, overlap);
}
```

### 踩过的坑：必须用区间重叠，不能从段起点算

第一版实现写成 `Math.min(ageYears - start, span)`，在 y9 时会把 4–7 段
（start=3, span=4）也乘进去，得到 y9 = 0.1994 —— **y8(0.4000) → y9(0.1994)
的假跳变**。改用区间重叠 `min(age, segEnd) − max(8, segStart)` 后，
y9 = 0.4000 × 0.93 = 0.3720，衔接连续。

### 独立常量而非复用 TRACTOR_EXPERT_AGE_MAX_YEAR

`TRACTOR_EXPERT_AGE_MAX_YEAR`（=8）语义是「拖拉机专家样本的保护上限」，
本文引入的 `AGE_TABLE_LINEAR_MAX_YEAR`（=8）语义是「数学形式的分界」。
两者当前同为 8 但含义不同，日后调整其一不应隐式改变另一个。

### 顺带修掉的测试基建缺陷

`tests/valuation-regression.test.ts` 里有个注释写着「与源码一致」的
`calcYearFactor` 辅助函数，实际是**旧线性版的独立副本**。源码改复利后副本未同步，
导致断言拿旧值 0.1000 去比新值 0.2843 而误报失败。

已改为直接委托 `calcAgeTableResidual`，并补 `category` 参数
（原签名无 category，跨白名单品类时会与源码判定分叉）。这正是
「两份实现导致口径漂移」的教科书案例 —— 与 `brand-data.ts` 注释里
「避免两处各写一份导致口径漂移」的初衷完全相反。

## 六、新增的结构护栏

新增 6 条断言锁住不变量，防止回退到线性减法：

1. y8 = 0.4000（专家锚点段一位未动）
2. y7→y8 无跳变（分段衔接连续）
3. y13 ∈ (0.25, 0.32)（对照实测大方捆 0.315）
4. **y13 > y20**（核心 bug 回归护栏：旧实现两者都锁死在 0.10）
5. y30 > 0.10（未跌到地板；理论值 0.40×0.93⁴×0.95¹⁷ = 0.1189）
6. **y1→y30 严格单调递减**（无平台期 = 无触底锁死）

## 七、遗留项与诚实的局限

1. **`7/8/7/5` 这组费率本身仍无可追溯推导**。commit `76888c4` 声称基于 520 万条
   补贴数据，但仓库内无该数据集、无生成脚本，相关报告仅是规划文档。
   本次改造修正了**数学形式**（年率 vs 年减量），但**没有为费率本身提供依据**。
   （同一文件里的 `HOURS_DEPRECIATION_CURVE` 有完整标定记录，机龄表没有。）

2. **y9/y10 段的处理含有隐含假设**。C 方案假设 y9 起就按复利走，但 8–12 段名义上
   仍是 7%/yr 的线性段，只是数学形式改为复利。若将来拿到 9–12 年的成交价样本，
   这一段最需要重新校准。

3. **10–15 年段的中国市场证据仍然很薄**：仅 2 个独立点且相互矛盾
   （大方捆 0.293/0.315 倾向本方案，小方捆 0.138 倾向旧机龄表）。
   小方捆那个 2 万很可能是事故机或配件机。

4. **补贴数据在本决策上帮不上忙**。国内青饲料收获机补贴全国封顶 15 万/台，
   补贴库给不出百万级机价残值。

5. **打捆机品类未进 ASABE 白名单**，仍走本改造后的机龄表。若后续拿到
   打捆机的成交价样本（≥1 份），应重新评估是否纳入白名单。

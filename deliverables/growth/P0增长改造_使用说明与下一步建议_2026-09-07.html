1. AI 估值留资引擎 —— 使用说明

1.1 访客会看到什么（三步漏斗）

  1. 填参数 → 出模糊结果。访客选品牌/品类/型号/年份/小时数/成色，点估值，拿到一个 ±12% 的价格区间（如 36.9 万 – 47.1 万，中间价 42.0 万），并标注「置信度 85%」。
    关键：此时公式拆解、基准价、品牌系数全部为空，前端拿不到任何精确值——这是故意的，防止绕过留资。
  2. 用满 3 次 → 触发门槛。同一 IP 当天第 4 次调用会被挡下，页面提示「今日免费估值次数已用完」，引导留邮箱或注册登录。
  3. 留邮箱 → 解锁精确值。输入邮箱后，服务端重新算一遍（不信任前端传值），返回精确估值 + 完整拆解，同时把这条线索写进 ValuationLead 表。

运营要点：同一个邮箱 + 同一组参数重复提交，会直接返回缓存结果（cached=true），不会重复插数据。所以你不用担心同一个人刷出几十条脏数据。

1.3 运营怎么查留资（重要）

⚠️ 现状：还没有后台页面。目前留资只能直连数据库查。这是本次改造最大的落地缺口，已在第 4 节列为 P0-3。

境外 .com（Neon / PostgreSQL）

-- 最近 100 条留资线索
SELECT "createdAt", email, locale,
       "valuationParams"->>'brand'   AS brand,
       "valuationParams"->>'category' AS category,
       "valuationParams"->>'year'     AS year,
       source
FROM "ValuationLead"
ORDER BY "createdAt" DESC
LIMIT 100;

-- 按天看留资量
SELECT DATE("createdAt") AS d, COUNT(*) AS leads,
       COUNT(DISTINCT email) AS uniq_emails
FROM "ValuationLead"
GROUP BY 1 ORDER BY 1 DESC;

境内 .cn（ECS 上的 cn-postgres）

# 1) 进容器
docker exec -it cn-postgres psql -U cn_app -d usedfarmmach_cn

# 2) 查线索（同上 SQL）
SELECT "createdAt", email, locale, "valuationParams"->>'brand' AS brand
FROM "ValuationLead" ORDER BY "createdAt" DESC LIMIT 50;

需要你清理的一条测试数据：我在验证 .cn 链路时留下了一行测试留资，请执行下面这条删除（.com 的测试数据我已清掉，.cn 需要你在 ECS 上跑）：

DELETE FROM "ValuationLead" WHERE email = 'p0-selftest-cn@usedfarmmach.com';

2. 卖家发布 —— 使用说明

发布页改成了三步向导，必填从 24 项压到 8 项，实测填完约 2 分钟。

2.1 发布三步

  1. 上传图片（必填，至少 1 张，最多 10 张）　单张 ≤10MB，超了会自动压缩。免费档 10 张，旗舰档 20 张，企业档 50 张。
  2. 上传运转视频（选填，最多 3 个）　强烈建议传——带作业视频的机器询盘率明显更高。
  3. 填表单　7 个必填字段 + 折叠的 11 个选填字段。

2.2 必填字段（7 个 + 1 张图）

字段说明备注
品牌 *如 CLAAS / New Holland / Krone下拉选择
品类 *方捆机 / 圆捆机 / 青贮机等下拉选择
型号 *如 QUADRANT 2200手填
出厂年份 *默认 2020影响折旧系数
工况 / 小时数 *如 1200本次新增的必填项，买家最关心的字段之一
价格（元）*卖家报价可与 AI 估值对照
产地 *机器所在地影响物流成本估算

2.3 选填字段（折叠在「更多信息」里）

额定马力 (HP) · 发动机类型 · 驱动方式 · 主要配置 · 总长 · 总宽 · 总高 · 整机重量 (KG) · 价格模式 · 贸易术语 · 发货港口

为什么要折叠而不是删掉？这些字段对估值和搜索排名有用，但会吓跑新卖家。折叠后：想快发的填 7 项就能上线，想冲曝光的展开补全——填得越全，搜索权重越高。

2.4 估值预填（省时设计）

如果卖家是从 AI 估值页点「发布这台机器」跳过来的，品牌/型号/年份/马力等会自动带进表单，顶部出现提示条「已为你带入 AI 估值信息，确认后即可发布」，旁边有「清除」按钮可以一键清空重填。

4. 下一步完善建议

按「先止血、再收钱、后放大」排序。前三条是现在就该做的，其中前两条是我在写这份文档时核对代码发现的线上问题。

P0-1 合规称谓写错了，必须立刻改

问题：会员页底部的协会背书，中文版写的是

中国农业机械流通协会·二手农机流通分会 副会长单位

正确写法应是：

中国农业机械流通协会二手农机流通分会 副会长单位

① 协会全称是「中国农业机械流通协会」，不能简写成「中国农业机械流通协会」；② 「分会」二字不能省；③ 中间那个「·」分隔符去掉。
英文版是对的（China Association of Agricultural Machinery Circulation），只有中文简写了——而这句恰恰只在 .cn 境内站显示，属于对国内用户的正式背书，是明确的合规红线。
改动位置：messages/zh.json → membership.trust.cn　（一行，改完重新部署 .cn）

P0-2 免费档赠分文案与代码不一致（10 vs 20）

问题：会员页免费档写「注册赠送 10 积分」，但代码里已经是 20（constants.ts:47 registerGift: 20、permissions.ts:16 credits: 20）。
8 个语言文件全部写的是 10，全部要改。
影响：实际发 20 分，页面上写 10 分 —— 属于少宣传了自己的权益，白扔了一半的吸引力。
改动位置：messages/*.json（8 个）→ membership.benefits.free 最后一条。

P0-3 留资进得来、看不见 —— 缺后台与通知

现在线索躺在数据库里，没人会主动去查，等于留资引擎只跑了一半。建议补三件事：

  • 后台留资列表页：/admin/leads，表格展示 时间/邮箱/品牌/品类/年份/来源站点，支持按天筛选和导出 CSV。（约 1 个页面 + 1 个 API，工作量小）
  • 企微实时推送：有新留资就推到「神雕套利运营日报」小群（webkey 已配好，复用现有推送模块即可）。这条最关键——销售要能在 5 分钟内联系上刚估完值的客户，转化率差好几倍。
  • 自动回复邮件：留邮箱后立刻发一封带精确估值报告的邮件，既是交付也是二次触达。

P1-1 打通收钱（变现的真正起点）

  1. .cn 微信支付优先。境内已有 ICP 备案，走微信支付商户号合规性最顺。需要确认商户号归属与签约，然后接 Native/JSAPI 支付 + 回调。
  2. .com Stripe。三张表已建，只差密钥。需要在 Vercel 配 STRIPE_SECRET_KEY / STRIPE_WEBHOOK_SECRET；同时确认境外收款主体。
  3. 深度报告先做在线支付试点。现在是静态收款码 + 用户自点「我已付款」，既体验差又对不上账。改成在线支付带回调，跑通一单完整闭环，再复制到会员订阅。

P1-2 补齐 7 个语种的翻译

新增的三个文案命名空间，目前只有中文是真翻译，其余 7 语（en/es/pt/ar/fr/hi/ru）还挂着 _todoTranslate 标记、实际显示英文占位。
优先级建议：en → ru（俄语区是主战场）→ es/pt（南美）→ ar（中东）→ fr（非洲）→ hi。

P1-3 补埋点，否则优化全靠猜

全站目前只有 Yandex Metrika（只覆盖俄语用户），注册 / 发布 / 估值 / 解锁 这四个关键转化事件一个都没埋。
建议：.cn 接百度统计，.com 接 GA4；至少埋 5 个事件：valuation_start / valuation_blurred_shown / lead_unlocked / register / publish_submit。
有了这个，才能回答「留资率是多少」「哪一步流失最多」——现在这两个问题答不上来。

P2-1 留资后的自动化培育

  • 留资 24 小时内未注册 → 自动发一封「同类机型在售清单」；
  • 留资但 7 天未发布 → 推送「发布补贴/置位优惠」；
  • 按品牌聚类：留资 CLAAS 的客户，推 CLAAS 相关货源与行情。

P2-2 小程序同步

本次改造只在两端 Web 站生效，小程序还没跟上。建议同步顺序：AI 估值留资 → 发布简化 → 会员页。（会员支付在小程序内需注意平台规则，先做展示、暂不做支付。）

P2-3 数据库密码轮换

Neon neondb_owner 连接串已在会话中明文出现，建议存 Bitwarden 后择期轮换，同步更新 Vercel 环境变量 + GitHub Actions secret。不紧急，但别拖过这个月。
